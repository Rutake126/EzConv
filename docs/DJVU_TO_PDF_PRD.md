## 1. 背景与核心痛点分析 (Background & Problem Statement)

### 1.1 业务背景
DjVu 格式作为 20 世纪 90 年代由 AT&T 实验室（Yann LeCun 等人）针对高分辨率扫描文档开发的格式，具有极其卓越的压缩比与文字清晰度，曾广泛应用于数字图书馆、学术古籍、外文教科书及扫描文献分发中。
然而在当前移动办公和跨平台阅读生态中：
- **兼容性极差**：主流浏览器（Chrome/Edge）、移动端阅读器（iPad/Android）、多数电子书阅读器（Kindle/微信读书）对 DjVu 均缺乏原生渲染支持；
- **行业事实标准为 PDF**：用户迫切需要将手中的高质量 DjVu 电子书无痛转换为通用的 PDF 格式。

### 1.2 现有开源转换工具的三大“致命死穴”

目前互联网上现有的 DjVu 转 PDF 工具（如 `djvu2pdf`、在线转换网站、格式工厂等）普遍存在以下严重痛点：

```
                    ┌─────────────────────────┐
                    │    传统方案：暴力光栅化    │
                    │ (Flatten to RGB Bitmap) │
                    └────────────┬────────────┘
                                 │
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
【痛点 1：体积恶性膨胀】                          【痛点 2：文字清晰度劣化】
原 10MB DjVu 膨胀到 150MB~300MB                   若采用 JPEG 压缩来压低体积，
(膨胀 10x ~ 30x，手机/网盘寸步难行)                 文字边缘产生严重振铃噪声和模糊毛刺
                                 │
                                 ▼
                    【痛点 3：高价值元数据全丢】
                    原书 OCR 搜索文字层丢失（无法搜索复制）
                    原书大纲目录树丢失（阅读极难导航）
```

### 1.3 核心技术矛盾剖析

DjVu 之所以能够兼顾“极小体积”与“极高清晰度”，其本质是采用了 **MRC (Mixed Raster Content，混合栅格内容)** 架构：
- **文字掩码层 (Mask)**：300~600 DPI 极高分辨率的 1-bit 二值黑白图，采用 **JB2** 算法（基于字符符号字典复用与算术编码），将文字笔画压缩至极限，边缘如矢量般锐利；
- **背景/图像层 (Background)**：采用低分辨率（如 100 DPI）的 **IW44** 小波压缩，专职存储纸张纹理和彩色插图；
- **文本/书签层**：独立嵌入字符 Bounding Box、识别内容及目录树。

**传统方案之所以失败，是因为将原本分层的结构“粗暴打平”（Flatten）成单一全彩位图**。要实现“保证清晰度且体积不膨胀”，PDF 必须**原生镜像 DjVu 的 MRC 架构**。

## 2. GitHub 与业界热门方案深度调研 (Technical Benchmark)

针对 GitHub、开源社区与前沿文档处理技术，调研结论对比如下：

| 方案 / 工具 | 技术原理 | 清晰度 | 体积控制 | OCR/书签 | 依赖复杂度 / 客户端适配性 | 综合评价 |
| :--- | :--- | :---: | :---: | :---: | :--- | :---: |
| **A. `pdfbeads` + `jbig2enc` + `djvulibre`**<br>(GitHub 黄金标准方案) | 拆分二值掩码用 **JBIG2** 符号压缩，背景用 **JPEG/JP2** 压缩，合成 MRC PDF | **极高 (100% 原生锐利)** | **极佳 (0.9x ~ 1.3x 原体积)** | 支持 (需 hocr/txtz 脚本辅助) | **极复杂**：依赖 Ruby 环境、RMagick、FreeType、Ghostscript 等，Windows 下极难单文件便携化。 | ⭐⭐⭐⭐<br>(质量顶级，但环境太重) |
| **B. `djvu2pdf-docker` / `ocrmypdf` 容器流** | Docker 封装 Linux 工具链胶水脚本 | 高 | 良好 | 支持 | **不可接受**：需安装 Docker 容器，体积数 GB，完全不符合 EzConv 绿色轻量的定位。 | ⭐⭐<br>(无法作为桌面客户端内置) |
| **C. `ddjvu` + `Ghostscript` 传统脚本** | `ddjvu` 导出 TIFF/PPM，Ghostscript 重封装 | 较差或模糊 | **极差 (暴涨 5x~20x)** | 丢失 | 需外部 `gs` 命令行。 | ⭐<br>(淘汰方案，正反面教材) |
| **D. `PyMuPDF` / `pdf2djvu` 反向管道** | 渲染页面为 Image 后用 CCITT G4 重压 | 中等 (丢彩色背景) | 良好 (仅黑白文档) | 部分支持 | Python 运行时，对彩色扫描件处理失真。 | ⭐⭐⭐<br>(仅适合纯黑白，不通用) |
| **E. 原生 C++ 架构 (EzConv 建议方案)**<br>`libdjvulibre` + `jbig2enc` + PDF MRC 流式合成 | 静态内嵌 C++ 解析，原生提取 JB2 掩码转 JBIG2，复用 OpenJPEG 压背景，直接生成 PDF | **极高 (原生 1-bit 二值锐利)** | **极佳 (控制在 1.0x~1.4x)** | **原生支持 (提取 TXTz/NAVI 直接注入 PDF)** | **完美适配**：C++ 静态编译，零外部运行时，完美延续 EzConv 单文件绿色运行特性！ | ⭐⭐⭐⭐⭐<br>**(推荐实施目标)** |

## 3. 产品定位与核心目标 (Objectives & Key Results)

### 3.1 核心目标
在 EzConv 中实现真正工业级、开箱即用的 **DjVu ➜ PDF** 转换能力：
1. **体积不膨胀**：生成的 PDF 与原 DjVu 体积比稳定控制在 **1.0x ~ 1.5x** 以内（纯黑白古籍/论文甚至可能比原文件更小），彻底终结体积膨胀 10 倍的顽疾。
2. **文字高保真**：文字笔画保持原生 1-bit 二值高分辨率边缘（300~600 DPI），绝不出现 JPEG 蚊状噪点与发虚模糊。
3. **元数据完整保留**：无损继承 DjVu 原文档的 **OCR 隐藏文本层**（可检索、可划线复制）与 **多级目录书签（TOC）**。
4. **绿色单文件体验**：零外部 Python/Docker/Ghostscript 依赖，延续 EzConv 极简单可执行文件运行。

## 4. 功能需求规格 (Functional Specifications)

### 4.1 输入与文件解析支持
- **文件支持**：支持 `.djvu` / `.djv` 格式（单页文档、多页捆绑文档 Bundled、多文件间接文档 Indirect）。
- **交互方式**：
  - 支持直接拖拽单文件、多选文件或包含 DjVu 的书籍文件夹至 EzConv 托盘；
  - 支持与原有 `.jp2` / `.j2k` 任务混排自动识别（根据文件扩展名与文件头 Magic Bytes 自动分发转换通道）。

### 4.2 核心转换模式（在“查看所有选项”中可自由切换）

| 模式名称 | 适用场景 | 底层技术实现 | 预期体积与效果 |
| :--- | :--- | :--- | :--- |
| **1. 智能分层模式 (Smart MRC)**<br>*(推荐，默认模式)* | 大多数扫描文献、带彩色插图/红印章的古籍、图文混排教科书 | **文字/线条掩码**：JBIG2 压缩（保持 300~600 DPI 二值锐度）<br>**背景底纹/照片**：JPEG / JPEG 2000（适度下采样并复用 OpenJPEG）<br>PDF 中通过 `/ImageMask` 与叠加层渲染 | 体积与原 DjVu 基本相当（1.0x~1.3x），文字边缘极度锐利，彩色插图完好。 |
| **2. 极速黑白无损模式 (Lossless JBIG2)** | 纯文字书籍、论文、纯黑白档案、无彩色内容的扫描件 | 提取纯二值 Mask，跳过背景层渲染，直接全书采用 JBIG2 跨页字典符号复用压缩 | 体积达到极限（通常甚至小于原 DjVu），渲染速度最快，翻页极度丝滑。 |
| **3. 高保真全彩平铺模式 (Photo High-Q)** | 摄影画册、全彩地图、复杂油画扫描、无法分离掩码的艺术类 DjVu | 全页栅格化，使用高质量 JPEG / JPEG 2000 压缩，支持 1~100 质量滑块调节 | 适用于 MRC 无法合理分层的极端艺术画册，体积由质量滑块控制。 |

### 4.3 关键元数据保留功能
- **全文检索与文字复制 (Searchable PDF)**：
  - 自动读取 DjVu 的 `TXTz` / `TXTa` 隐藏文本层，获取段落、行、词级的精确矩形坐标 (`Bounding Box`)；
  - 转换为 PDF 标准的隐形文本渲染模式（Text Rendering Mode 3，`3 Tr`），精确贴合在上层文字图像正下方；
  - 用户在 Acrobat / Edge / Chrome 等阅读器中可直接使用 `Ctrl+F` 搜词，鼠标平滑选词划线、做笔记和复制。
- **层级目录书签 (Table of Contents / Bookmarks)**：
  - 解析 DjVu 内部的 `NAVI` 导航 chunk；
  - 将多级嵌套书签完整转化为 PDF 标准的 `/Outlines` 书签树，点击目录自动定位到对应页码与视口。
- **基础元数据透传**：
  - 提取 DjVu 文件的 Title, Author, CreationDate, Subject 等属性，注入 PDF 的 `/Info` 字典。

### 4.4 高级参数配置项（Advanced Options Drawer）
在 UI 的展开配置抽屉中提供针对 DjVu ➜ PDF 的专有调节项：
- **JBIG2 编码策略**：
  - `无损模式 (Lossless)`：100% 逐像素无损保留二值文字；
  - `感知无损符号去重 (Lossy Match)`：启用相似符号匹配阈值（默认 0.85），大幅缩小体积且人眼无法感知差异。
- **背景质量滑块**：针对智能 MRC 模式中的背景图层，提供 1~100 压缩质量选项（默认 75）。
- **保留项勾选开关**：
  - [x] 保留 OCR 识别文本（可复制/搜索）
  - [x] 保留文档目录书签
- **输出配置**：
  - 输出路径：原目录 / 自定义目录；
  - 冲突处理：自动重命名 / 覆盖。

## 5. UI / UX 交互设计需求 (User Experience)

### 5.1 界面视觉契合
- **保持现有核心风格**：深度融入 EzConv 现有的居中极简虚线框、深浅色模式自适应以及平滑的微动画；
- **智能格式联动**：
  - 当拖入 `.djvu` 文件时，底部主目标格式下拉框自动切换并高亮选中 **`PDF`**；
  - “查看所有选项”抽屉动态展开针对 PDF 的专用配置面板（如智能 MRC、OCR 保留、JBIG2 开关）。

### 5.2 进度与转换反馈
- **多任务列表与进度卡片**：
  - 显示当前处理阶段：`[解析页面] -> [JBIG2 编码] -> [写入 PDF] -> [注入元数据]`；
  - 单任务多页进度条：显示当前页码与总页码（如 `处理中: 第 45/320 页`）。
- **成果对比直观展示**：
  - 转换完成后，列表卡片右侧展示转换前后体积对比胶囊标签，例如：
    - `DjVu: 18.2 MB  ➜  PDF: 19.5 MB (+7.1%)`（直观验证“未发生膨胀”）；
  - 提供 **`打开文件`** 与 **`定位目录`** 快捷按钮。

## 6. 技术实现路线与架构设计 (Technical Architecture)

```
                       ┌───────────────────────────────┐
                       │     输入文件 (input.djvu)      │
                       └───────────────┬───────────────┘
                                       │
                        libdjvulibre 解析器 (C++17)
                                       │
     ┌─────────────────────────────────┼─────────────────────────────────┐
     ▼                                 ▼                                 ▼
【Mask 掩码层提取】              【Background 背景提取】              【元数据提取】
1-bit 二值文字图 (300-600DPI)     低分辨率小波背景 (100DPI)            TXTz 文本坐标 + NAVI 目录
     │                                 │                                 │
     ▼                                 ▼                                 │
jbig2enc 编码引擎                 OpenJPEG / TurboJPEG 编码               │
生成 JBIG2 码流 (字典复用)        生成 JPEG / JP2 码流                    │
     │                                 │                                 │
     └────────────────┬────────────────┘                                 │
                      ▼                                                  ▼
           【PDF MRC 流式合成引擎】 ◄─────────────────────────────────────┘
           - 创建 Page 视口与变换矩阵
           - 写入 Background Image (低清底层)
           - 写入 Mask ImageMask (高清顶层)
           - 写入 3 Tr 隐形 OCR 文本层
           - 写入 Catalog Outlines 目录树
                      │
                      ▼
           ┌───────────────────────────────┐
           │      输出文件 (output.pdf)     │
           └───────────────────────────────┘
```

### 6.1 核心组件与选型建议

1. **DjVu 解码与解析：`libdjvulibre`**
   - 官方标准 C++ 实现，支持流式解析 DjVuPage。
   - 抽取：`DjVuImage::get_bitmap()`（用于二值掩码）、`DjVuImage::get_bg_image()`（用于背景）、`DjVuText`（用于 OCR 文本）、`DjVuDocument::get_outline()`（用于目录）。
2. **二值文字高压缩编码：`jbig2enc` (Modified / Embedded)**
   - 业界公认最好的开源 JBIG2 编码器（基于 Leptonica 二值化/连接域分析与 JBIG2 符号去重）。
   - 将其核心 C/C++ 代码裁剪并直接内嵌到 EzConv，静态编译，输出 PDF 规范兼容的 JBIG2Globals (共享字典) 与 JBIG2Stream。
3. **背景图压缩：复用现有 `OpenJPEG`**
   - EzConv 当前已深度集成并静态链接了 `OpenJPEG 2.5.2`；
   - PDF 原生支持 `/JPXDecode`（JPEG 2000 Filter），因此背景图可无缝复用现有 OpenJPEG 进行高质量/小体积编码，无需额外引入外部库。
4. **PDF 生成引擎：轻量级 C++ PDF Writer**
   - PDF 规范中嵌入 JBIG2 和 JPEG2000 的结构非常精炼（Image XObject、`/Filter /JBIG2Decode`、`/Filter /JPXDecode`、`/ImageMask true`）；
   - 可选用成熟轻量的开源 C++ 库（如 `minipdf` / `hpdf` / 现代化轻量 PDF 写入模块），支持内存流式写入磁盘，避免大文件内存占用过高。

## 7. 非功能性需求与验收指标 (NFR & Acceptance Criteria)

### 7.1 体积控制指标 (Size Ratio)
| 文档类型 | 目标体积比 (PDF / DjVu) | 验收标准 |
| :--- | :--- | :--- |
| **纯文字扫描件 / 论文** | **0.8x ~ 1.1x** | 不得超过原文件体积的 1.15 倍 |
| **图文混排书籍 (带插图/底色)** | **1.1x ~ 1.4x** | 严格控制在 1.5 倍以内，杜绝 5x 以上恶性膨胀 |
| **全彩复杂画册** | **1.3x ~ 1.8x** | 依据画质滑块可控调节 |

### 7.2 清晰度指标 (Sharpness)
- 在任何现代 PDF 阅读器中放大至 **400%**：
  - 文字笔画边缘必须保持原生 1-bit 二值锐利，无 DCT 模糊；
  - 笔画与字形特征与原 DjVu 1:1 精确对齐。

### 7.3 稳定性与资源占用 (Stability & Performance)
- **内存峰值控制**：对于包含 1000 页以上的超大 DjVu 文档，采用分批流式转换与分页落盘机制，单进程内存峰值限制在 **300 MB** 以内，坚决杜绝 OOM 闪退。
- **并发性能**：复用 EzConv 原生 `ThreadPool`，支持多页并行渲染与编码。
